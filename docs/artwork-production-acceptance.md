```sh
cd services/artwork-service
```

`scripts/acceptance.py` owns the service process (it kills and restarts it):
it creates a fresh `~/.local/share/metal-craft-artwork/acceptance`, generates
a random token (never printed or stored), starts `python -m artwork_service
serve` on `127.0.0.1:8766` with 2 workers and drives only the public HTTP API.
Its report is `acceptance-report.json` in that directory, with the downloaded
packages and the captured responses under `evidence/`.

**How real images reach the service.** The test-only setting
`ARTWORK_TEST_FIXTURE_DIR` (off by default; logged as a warning when set)
serves `test-fixture://local/<name>` source URLs from one directory, plain file
names only. Without it such URLs fail with `SOURCE_HOST_NOT_ALLOWED`, like any
non-HTTPS URL (unit-tested). All other URLs still go through the HTTPS
allowlist and SSRF checks, which the disallowed-host check exercises.

## Admin dev runtime → service loopback

With the dev service running and `apps/admin/.dev.vars`
(`ARTWORK_PRODUCTION_ENABLED=true`, `ARTWORK_SERVICE_ORIGIN=http://127.0.0.1:8766`,
the token), `pnpm --filter @metal/admin dev` was started and a temporary,
uncommitted handler was added to `src/server.ts` that runs the same kind of
`fetch` as `production.server.ts` (bearer token, `redirect: "manual"`, 15 s
timeout) and parses the answer with the admin's `parseHealth`. Result:

```json
{"runtime":"Cloudflare-Workers","status":200,"ms":5,
 "health":{"service_version":"0.1.0","worker_ready":true,"queue":{"queued":0,"running":0},
 "tracer_version":"opencv-contours/1.0.0","solver_version":"0.1.1218","exporter_version":"artwork-dxf-1.0.0"},
 "unauthenticated_status":401}
```

So the workerd dev runtime reaches `127.0.0.1:8766`, and the service rejects
the same request without the token. The handler was then removed
(`git checkout src/server.ts`, probe path back to 404). Signed-in UI flows were
not exercised: they need an Echoray operator sign-in.

## Fixes made during integration

- **Admin rejected every real master** (`apps/admin/src/features/production/contracts.ts`):
  tracing warnings are `{code, message, details}` objects, but the admin
  parser required strings, so all three fixtures (each has
  `SMALL_OPENINGS_FILLED`) failed with "Unexpected artwork service response".
  Batch drafts with an unknown/foreign master have `null` actual sizes, which
  the parser also rejected. Fixed, and `apps/admin/tests/service-responses.test.ts`
  now checks every parser against responses captured from the real service.
- **Traced concave shapes never reached the solver** (`solver_adapter.py`):
  PackingSolver's own spacing inflation failed on the traced comb ("face area
  is not positive"), so the job silently fell back to bounding boxes. The
  adapter now applies the gap itself (contours inflated by gap/2, bin grown by
  gap/2, solver spacing 0); regression test added.
- **DXF read-back was the bottleneck** (`dxf_export.py`): the 54-part batch
  spent ~70 s verifying DXFs (quadratic Hausdorff against every neighbour).
  Candidates are now filtered by bounds (sound: bounds differ by at most the
  Hausdorff distance) and distances use a segment index; the job went from
  105 s to 38 s with identical results.
- Test-only fixture source (`ARTWORK_TEST_FIXTURE_DIR`), ezdxf INFO logging
  silenced, independent JS DXF verifier with pytest hook.

## Remaining limitations

- PackingSolver's seed is not applied (bindings do not expose it); runs are
  time-bounded heuristics, not optimal.
- Insufficient stock: when not all parts fit `max_sheets`, the solver finds no
  all-items solution and the partial layout comes from the bounding-box
  baseline (18 of 54 placed). Counts are explicit and nothing is downloadable,
  but the partial placement is not optimized.
- `validation.min_gap_mm` is `null` for these layouts: the validator measures
  only pairs closer than gap + 1e-6 mm, and the collision contours keep every
  pair slightly farther apart than that, so the actual minimum gap is not
  reported (only that none is below the gap).
- Large traced parts make large files: about 9 MB per DXF sheet and 4 MB per
  SVG preview for the mixed batch.
- Fabrication-profile limits are unknown; geometric validity is not a cutting
  qualification.
- Not exercised locally: tracer upgrade, browser reload/network loss in a
  signed-in session, live catalog pagination, Windows/hosted admin/tunnel
  (Phase 6).
